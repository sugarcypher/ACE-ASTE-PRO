A security gate between the web and your AI agent

The same invisible-text defense that powers the AcePaste cleaner, placed in front of your agent's fetch. Pages that hide instructions from people are refused before the model reads them. Every refusal is logged and every verdict gets a signed receipt.

Anything the model would receive that a person looking at the same page would not see is suspect by default.

Install in one step

Add it to any agent that speaks the Model Context Protocol, such as Claude Desktop, Claude Code or Cursor. The agent then reads the web through ingress_fetch and ingress_scan instead of a raw fetch.

{ "mcpServers": { "acepaste-ingress": { "command": "npx", "args": ["-y", "@acepaste/ingress-mcp@0.9.30"], "env": { "INGRESS_SANDBOX": "off", "INGRESS_LOG": "/absolute/path/acepaste-ingress.jsonl" } } } }

Want receipts anyone can verify? Make a key pair once with npx -p @acepaste/ingress ingress --keygen and point INGRESS_SIGNING_PRIVATE_KEY_FILE at the private key. To try one page from a terminal:

npx @acepaste/ingress https://example.com

It runs on your machine or your own server. No ThinkWell Labs service sits in the loop, and your logs and receipts stay with you.

What it gives you

Most tools score text after it has been pulled out of the page, so some of the evidence is already gone. Ingress works on the page itself, and it refuses by default.

Refuses by default

Suspect content waits for a person

A refused page never reaches the model. A person can release a suspect page, but not a hostile one. Any internal error counts as a refusal, never a pass.

Sees the blind spots

What the model reads but you don't

Invisible Unicode (tag characters, zero-width channels, bidi overrides, look-alike letters), text hidden by CSS or coloured to match its background, and payloads tucked into attributes, comments, SVG or srcdoc.

Catches cloaking

One page for you, another for the bot

It fetches twice and compares, which catches sites that detect automation and serve agents a different page. It can also render the page in a throwaway browser and compare again.

Signed receipts

Proof of what your agent read

Every verdict, clean ones included, gets a hash-chained receipt signed with ECDSA P-256. Anyone with the public key can check it, and nobody without the private key can forge one.

Quarantine

Block a source and see where it already reached

Quarantine a host or URL and future fetches of it are refused. You also get its blast radius: every earlier receipt from that source, including what was delivered.

Action broker

Outside content can't approve itself

Once a run has read outside content, side-effecting tool calls need a person to approve that exact call. The approval comes through a channel the model can't drive, a native dialog on macOS.

Secrets stay out

Credentials are redacted

Cloud, Git, registry, payment and model-provider tokens and private keys are identified by type, redacted from delivered text and never written to a log.

Environment audit

Has something already got in?

ingress audit checks your machine for anything that changes what agents receive before a gate sees it: hosts and DNS, proxies, browser extensions and policies, trusted certificates, MCP configs and hooks.

Three verdicts

Every page or piece of text gets one. Only clean content is delivered.

Clean

The model gets the visible text inside a provenance envelope, with a signed receipt.

Suspect

Nothing is delivered. A person can override it, and the receipt records that they did.

Hostile

Nothing is delivered and it can't be overridden. The refusal is logged.

Every capture and every refusal is on the record

Ingress keeps two records. Both are files you own, on the machine or server where it runs.

The refusal log

One JSON line per refusal, written to INGRESS_LOG.

  • What was found and where: the page location of each finding, the matched excerpt and its digest.
  • Hidden payloads decoded into readable text: tag characters, base64, hex and the rest.
  • The hosts a payload tried to reach, and the redirect chain the fetch followed.
  • Each finding is labelled as an inference or a hypothesis, with a confidence band and the harmless explanation a reviewer should rule out.

The receipt log

One receipt per verdict, clean or refused.

  • What came in, what was delivered and what was stripped, each fixed by a digest.
  • Chained to the receipt before it, so a deleted or edited entry shows.
  • With @acepaste/ingress-http: search by URL, host, verdict, finding type or date, browse it in /console and export it as JSON.
  • Verify any receipt offline with ingress --verify.

    Seeing AcePasteIngress in your server logs?

    An AI agent fetched your page through AcePaste Ingress. Its own user agent is AcePasteIngress/0.9 (+https://acepaste.xyz/ingress) (0.8 in releases before 0.9.31). It fetches only the page the agent asked for. It reads it twice to check for cloaking: once as an AI assistant (ChatGPT-User, Claude-User or Perplexity-User) and once as a desktop browser, and in a headless browser too if its operator turned that on. It uses its own name when a site refuses AI assistants, or always if its operator chooses. It doesn't crawl or index anything. Everything it contacts.

    The person who runs the agent operates it, not ThinkWell Labs, so we can't see or stop a particular instance. To keep agents off your site, use robots.txt or block that user agent. Questions: help@acepaste.xyz.

    What it doesn't do

    • It keeps its judgement of plain visible prose narrow on purpose. Only the strongest instruction shapes in visible text are refused, and those can be overridden. Its weight is on what the model can't see.
    • The broker governs only the calls routed through it. A tool the agent can reach directly is outside it.
    • It's pre-1.0, so interfaces may still change.
